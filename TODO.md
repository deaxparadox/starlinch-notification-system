- BUG-20260823-0403 — Web Push always notified only one of a user's devices, permanently, regardless of which device actually triggered the notification. Root cause: `_resolve_recipient()` in `backend/notifications/services.py` called `user.pushsubscription_set.first()` for the webpush channel, which deterministically returned whichever device subscribed first ever for that account (Django orders an unordered `.first()` by primary key) - every other subscribed device was silently ignored forever. Found by the user testing on Windows, Linux, and mobile: only the account's oldest-subscribed device (Linux) ever received a notification, no matter which device logged in. Also verified (via context7, OneSignal's current Web SDK docs) that the frontend's `OneSignal.User.PushSubscription.id` is genuinely per-device, ruling out a person-level-ID theory before committing to the backend fix. Fixed: `_resolve_recipients()` now returns every active `PushSubscription` for the user, and `_send_one`/`_send_to_one_recipient` send + log one attempt per device independently, so one stale device failing can't hide or block another device succeeding; overall channel status is "sent" if at least one device received it. Verified live against real OneSignal credentials: a real device + a deliberately fake device on the same account both logged their own row (real one "sent", fake one "failed" with its own error, real push notification actually delivered), overall result still "sent"; a user with zero subscriptions still logs exactly one clean "no recipient" row, not one per nonexistent device.
